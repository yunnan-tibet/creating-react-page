# 输入与复杂度分流

## 最小必要输入

先读相邻实现取得页面入口/路由、请求入口、UI 与表单能力、样式方式和验证命令。确认本次目标、数据来源、字段/按钮、主交互链及新增/编辑/只读模式。可从代码确定的事实不反复问用户；截图只能证明可见布局，不能证明接口、权限或保存规则。

缺少决定实现的输入时集中问必要问题，仍可交付不依赖该输入的设计。禁止把未提供字段写成真实 DTO、编造保存 URL，或以假成功回调宣布业务闭环。

## 三条路径

| 分类 | 判断 | 执行方式 |
| --- | --- | --- |
| 局部片段 | 已有页面中的一个按钮、字段、区块或组织修正 | 核对所属边界，最小改动，不补整套页面/路由/空目录 |
| 普通页面 | 一条清晰查询/编辑闭环，状态在页面或独立面板内即可表达 | 选一个主模式，列职责/状态/验收，按确认方案实现 |
| 复杂页面 | 上下文/焦点联动、多种编辑形态、异步依赖、脏数据保护、跨区块保存刷新等协调风险显著 | 先确认结构、状态所有者、契约与主链路，再分步交付 |

三个展示区块或文件较长不自动意味着复杂；协调风险而非固定行数/区块数决定路径。反之，一个表单也可能因多阶段审批/异步竞态需要复杂路径。

普通/复杂页最多选一个主模式，加必要的辅助模式，不为了“完整”同时套用所有模板。相邻实现已足够时不读全部示例或组件文档；使用特定组件前核对其真实 props、事件、表单/焦点 API，不猜测外部库或项目包装组件能力。

## 复杂页面的渐进实施

1. **结构/状态说明**：模块、区块职责、字段来源、服务边界、主链路与异常恢复；用简短表或图说明谁持有上下文、焦点 ID、查询、表单和保存状态。
2. **确认**：已有明确方案继续，不重新规划项目；新增且影响行为的选择先确认。未提供的权限、自动选中、关闭/丢弃规则不能擅定。
3. **骨架**：按现有布局与组件体系建立区块边界。不为简单上下文控件抽包装组件，不装库来匹配参考项目。
4. **一个闭环**：先使主区块或独立编辑区的真实查询/交互/失败恢复可验证，再接下一块。
5. **联动**：上下文切换 → 主数据 → 有效焦点 → 详情/编辑；保存成功 → 刷新/失效 → 保持或重新确认焦点。切换时取消旧请求、处理未保存输入。
6. **验收**：按本次模式跑相关测试及浏览器交互，区分骨架完成、单区块完成和整条链路完成。

先建立相关回归/失败测试，再实现。没有现成测试环境时报告缺口，不擅自加测试框架。分步不是用假数据伪装真实链路，也不是在一次任务里推进所有模块。

## 停止与交付

只读 Review 不写文件。缺权限/契约/设计选择时停止受阻部分；检查失败先定位，在本次范围且有新证据时修复重测，否则保留现场并报告。交付实际文件、可验收行为、证据及未验证项；不自动提交、发布或修改其他项目。
