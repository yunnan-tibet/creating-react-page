# 字段、常量与配置

## 字段规格先于组件

按实际页面需要列字段 key、含义、类型/可空性、数据来源、展示/编辑方式、选项来源、校验与提交转换。表格另核对列、排序/分页能力、标识和操作条件；按钮核对可见性/权限、禁用条件、loading 归属、成功结果与失败恢复。不要求给每个无歧义字段写冗长注释，单位、状态值、空值和有歧义含义必须说明。

- 不从字段名猜主键、权限、字典值或分页 envelope。后端数值/布尔类型不可为了统一选择框全部强转字符串。
- 表单值与 DTO 分开：日期、选择项、空串/undefined、可编辑字段等转换有明确边界，不将整个页面状态直接提交。
- 只有业务需要才增加编辑、删除、选择、批量操作。只读页不自动生成写接口或表单。

## 常量与字段配置的归属

- 业务状态/选项/正则/字段配置默认 constants/<domain>.ts；纯接口类型在 typings，UI-only 表单值/props 就近。
- 页面专属布局、面板派发表、小 UI 常量可在本页 constants.ts/config.ts；不把所有字面量机械提升，不把请求结果或登录态当静态配置。
- 仓库允许时用 as const 对象、字面量联合、类型明确的 Record 映射；不强制 TS enum、特殊枚举工具或额外依赖。值/标签映射、选项和分派 key 保持同一真源，避免魔法字符串散落。
- 字段/列静态部分与动态事件分离。需要 onEdit/onDelete/权限参数时用明确的配置工厂或在组件中组合，不让 constants import 页面/store 发起副作用。
- 组件库已有字段 schema、表单或表格 API 时核对后使用；没有这些能力就使用现有组件/原生控件，不安装库只为套示例。

## 分派、工具与样式

- 多种业务面板确需同一协议时，可用类型明确的组件映射/注册表；未知类型要有回退。少量清晰条件无需为消灭所有 switch/if 搭引擎。
- 通用树遍历、过滤、转换等纯函数放 utils 并独立验证；业务私有转换就近。先查已有工具，不能重复实现同名或近义万能函数。
- 沿用项目已有间距、字号、标题、反馈与控件体系，局部样式并置；不用固定像素规范、强制分栏依赖或特定组件名称替代设计。固定/可拖动面板按实际需求，验证最小可用宽度、长文案和窄屏。
- 查询/保存的 loading 绑定对应按钮或区块；反馈不得只靠颜色。表单有 label，列表 key 稳定，弹窗保持焦点、键盘、滚动和关闭策略；不能用全局样式修补局部问题。
